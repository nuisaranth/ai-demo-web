# Project Overview & Guidelines: AI & Digital Marketing Demo Web

## 1. Project Context & Purpose
- **Target Audience:** Digital Marketing and AI class students (non-tech, business owners, marketers) who only have 12 hours of total class time.
- **Goal:** A simple, high-performance Company Demo Website deployed instantly via a "Deploy to Vercel" button on GitHub.
- **Core Philosophy:** ZERO GitHub interaction for students after deployment, ZERO complex database setups, and NO raw code editing (e.g., NO editing `.yaml` or `.ts` files directly because it breaks easily). All interactions must be through a visual Admin UI.

## 2. Tech Stack Constraints
- **Framework:** Next.js (App Router) + TypeScript + Tailwind CSS.
- **State/Storage:** Browser's `localStorage` or `IndexedDB` ONLY (No external databases like PostgreSQL or MySQL to ensure frictionless Vercel deployment without API keys).

## 3. Site Architecture & Menu Structure
The demo website must contain the following standard company menus:
- `/` (Home): Hero section, services summary, and CTA button.
- `/about`: Company history and team profile section.
- `/services`: Layout showing core business services.
- `/portfolio`: Client logos and case study gallery.
- `/blog`: List of published articles and dynamic routes (`/blog/[slug]`) for reading articles.
- `/contact`: Contact details and a functional mockup contact form.
- `/admin`: The simplified control panel for students (hidden from main navigation but accessible via URL).

## 4. Required Features & Component Details

### A. Admin Dashboard (`/admin`)
Must be clean, intuitive, and easy for non-tech users to manage. It needs three core features:
1. **Google Analytics 4 Tracking Integration:**
   - A simple text input for "GA4 Measurement ID" (e.g., `G-XXXXXXXXXX`).
   - Saving this must persist the ID in the browser and dynamically inject the official Next.js script (`@next/third-parties/google`) into the root layout so students can test Google Analytics Real-time traffic immediately.
2. **Blog File Upload (Markdown Reader):**
   - An HTML file input allowing students to upload/browse a `.md` file generated by AI (Gemini/Claude).
   - Upon browsing the file, the system must parse the content immediately. If a file with the same name is uploaded, it must completely overwrite/reset the previous content.
   - Include a "Delete/Reset All" button to wipe the current mock database cleanly.
3. **Hybrid Editor Form & Image Uploader:**
   - Visual input fields to manually edit parsed data: `Title Tag`, `Meta Description`, and `Schema Type/Name`.
   - An Image management section allowing students to pick a mock image or upload a local image to replace the placeholder text in the Markdown, accompanied by a text field for entering `Alt Text`.

### B. SEO Inspector Component (Front-end Sidebar on `/blog/[slug]`)
On the live article page, display a split-screen or a prominent sidebar named "SEO Inspector" to visually educate students about On-Page SEO without using "View Source":
1. **Google Snippet Preview:** Simulate how the Title and Meta Description look on Google Search, featuring a visual indicator (Green/Red color bar) based on characters count limit (Title: 60 chars, Description: 150 chars).
2. **Heading Tag Counter:** Scan and display the total number of `<h1>`, `<h2>`, and `<h3>` tags used in the article. Alert with red text if more than one `<h1>` tag is detected.
3. **Schema Markup Validator:** Display the active structured data type (e.g., `Course`) to show how search crawlers understand the content entity.
4. **HTML Switcher Button (`</>`):** Toggle between the clean visual article view and the raw HTML string view, helping students understand what Google bots actually read (e.g., `<strong>`, `<a>`, `<img alt="...">`) without overwhelming them.

## 5. Development Instructions for Claude Code
- Keep components modular, well-styled with Tailwind CSS, and optimized for mobile devices.
- Focus on heavy client-side mock behaviors. Ensure that when a student refreshes the browser, data stored in `localStorage` remains intact.
- Do NOT add complex analytics metrics, social sharing Open Graph rules, or deep keyword research integrations to keep the runtime lightweight and avoid wasting valuable class time.
